## 2. Skill 调用前（无清单约束的 v1）

**当时的实现指令（提示词）**：

> 首页加第三个视图「我的收藏」，读 localStorage 的收藏记录，支持关键词筛选。

**实现结果**：只有关键词过滤 + 卡片渲染。

**浅检查**（日常做法：走一遍主路径，能跑就算过）：

| 步骤 | 结果 |
|---|---|
| ① 收藏 2 条 → 切入收藏视图 | 2 张卡片 ✓ |
| ② 输入「加油站」 | 1 张卡片 ✓ |
| ③ 输入不存在的词 | 0 张卡片，**列表区文字 = ""（彻底空白，无提示无出口）** ✗ |
| ④ 清空 | 恢复 2 张 ✓ |

浅检查结论：「主路径能跑通 → **看起来完成了**」——但第③步其实是死胡同。

## 3. Skill 调用后（按清单逐项断言）

**检查指令（提示词）**：

> 按 filter-check 清单逐项断言：A2 无结果 = 零条目 + 显示文案 + 有出口按钮（缺一即 FAIL）；B1 零数据态与筛空文案必须不同；C1 计数实时更新且 `aria-live="polite"`；C5 触控 ≥44px；C6 三档零溢出……

**Skill 实跑结果：FAIL(10)**

1. `A0b_条件筛选器存在` —— v1 没做结论 chip
2. `C1_计数反映关键词` —— 没有计数
3. `C1_计数aria_live` —— 读屏听不到
4. `A2_无结果_有文案` —— 无结果时一片空白
5. `A2_无结果_文案统一` —— 未用全站统一文案
6. `A2_无结果_有出口按钮` —— 死胡同
7. `A3_出口恢复_条数` —— 无出口可点
8. `A3_出口恢复_输入框已清空` —— 同上
9. `B1_零数据态_有引导文案` —— 一条都没收藏时也是空白
10. `B1_零数据态_与筛空文案不同` —— 两种空态无法区分

## 4. 按 FAIL 清单修复（v2）后复检

**修复指令**：按清单逐项补齐——结论 chip 组、计数（aria-live）、统一空态文案、出口按钮（带结论筛选时自动升级为「清空全部筛选」）、零收藏引导态（带「去卡片流看看」出口）、复用既有样式零新增色值。

**复检结果：ALL_PASS(49)**（feed 23 项回归 + favs 24 项 + 全局回归 2 项）

## 5. 差异总结（核心结论）

| 维度 | 无 Skill | 有 Skill |
|---|---|---|
| 检查深度 | 4 步主路径，「能跑 = 完成」 | 49 项逐条断言 |
| 发现的问题 | 0（10 项全部漏掉） | 10 项（含 2 个用户可感知的死胡同） |
| 修复后覆盖 | 主路径 | 三态 + 零数据态 + 无障碍 + 触控 + 溢出 + 回归 |
| 结论可信度 | 「看起来完成了」 | ALL_PASS(49) |

**一句话：没有 Skill 时我以为做完了；Skill 一跑才发现「无结果」和「零收藏」都是死胡同。**

## 6. Skill 自身的维护记录（本次顺带修掉）

- `filter-check.js` 初版遇到缺失元素会**崩溃**而非报 FAIL → 已加固（`textOf()` 安全取值，缺元素 = 该项 FAIL）。
- `frontend-rules` 的「首页两个视图」硬编码断言，在视图数变成 3 后**误报** → 已改为「视图数 = tab 数且 ≥2」+「切换实际生效」两条不依赖数量的强断言。
- 教训：**Skill 断言不要写死具体数量，要写「一致性 + 下限」**——产品演进时才不会误报。
