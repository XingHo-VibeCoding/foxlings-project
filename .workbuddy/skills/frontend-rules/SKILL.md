## 它管什么（一句话）

**把项目里已经拍板的前端规则固化成一份检查清单 + 一个可执行脚本：动手前照单核对，动手后一键验证，保证每次改动都不跑偏。**

## 何时用它

- 要改动 `index.html` / `detail.html` / `css/style.css` / `js/*.js` 里的任何一处（改之前读它，改之后跑它）
- 要新增页面、新增组件、新增按钮或交互
- 提交代码之前（「修改后验证」是提交的硬门槛，和 AGENTS.md 第九节的提交前抽查并列）

## 何时不用

- 只改文档（`PRD.md` / `AGENTS.md` / `research.md` / `RUN.md`），不碰前端文件
- 只改 `data/data.json` 的数据内容 —— 那条归 AGENTS.md 第九节的「信源核证」规则管
- 只是本地起服务器看效果

## 一、页面层级

来源：Day 7 骨架、Day 8 卡片流、Day 12 筛选器。

**每页固定四段式**，顺序不可变：

```
<header class="site-header">     ← 站名 + 口号（详情页多一个 .back-link 返回首页）
<main class="container">         ← 全部内容
<footer class="site-footer">     ← 免责声明
<script src="js/*.js">           ← 脚本放 body 末尾
```

| 规则 | 内容 |
|---|---|
| L1 | 所有内容必须装在 `.container` 里（`max-width: 760px` 居中 + 左右 `padding: 0 16px`），不得自行设固定宽度 |
| L2 | 页面内的「视图」用 `<section class="view" id="view-xxx">`，靠 `.view.active` 控制单显；同一时刻只有一个 `.active` |
| L3 | 切换视图 / 切换榜单档位用 `<nav>` + `<button class="tab">`；内容分块用 `<section>`；按钮一律原生 `<button>`（键盘天然可达） |
| L4 | 每个 `section.view` 要有 `aria-label`；筛选器容器要有 `role="group"` + `aria-label` |
| L5 | 详情页 `header` 里必须有 `.back-link` 指向 `index.html`（用户永远有路回家）；首页不放返回链接 |
| L6 | 每页 `<head>` 三件套：`<html lang="zh-CN">`、`<meta charset="UTF-8">`、viewport meta |

## 二、颜色与字体

来源：Day 9 设计审查。

### 颜色：只准用变量

所有颜色都走 `css/style.css` 的 `:root` 变量，**组件里不准新写十六进制色值**：

```css
--c-primary: #3b5bfd;   /* 主色：蓝 —— 主行动按钮、选中态、链接 */
--c-bg:      #f5f6fa;   /* 页面底色 */
--c-card:    #ffffff;   /* 卡片/面板底色 */
--c-text:    #2a2f3c;   /* 正文 */
--c-muted:   #59606e;   /* 次要文字 */

/* 结论四色（原色）：只用于大面积色块与状态按钮 */
--c-fake:    #e5484d;   /* 结论：假 */
--c-partial: #e69913;   /* 结论：部分属实 */
--c-true:    #18a058;   /* 结论：真 */
--c-doubt:   #7069fa;   /* 结论：存疑 */

/* 结论标签专用（浅底 + 深字）：12px 小字必须达 WCAG AA 4.5:1 */
--c-fake-soft:    #fdecec;  --c-fake-deep:    #a3121a;   /* 假：6.9:1 */
--c-partial-soft: #fdf4e3;  --c-partial-deep: #8a5300;   /* 部分属实：5.8:1 */
--c-true-soft:    #e8f6ed;  --c-true-deep:    #0f6b3a;   /* 真：5.9:1 */
--c-doubt-soft:   #efeffd;  --c-doubt-deep:   #4a44b8;   /* 存疑：6.6:1 */
```

| 规则 | 内容 |
|---|---|
| C1 | 上面 17 个色值变量 + `--radius` + `--shadow` + `--shadow-hover` 必须齐全，不得删改 |
| C2 | 正文文字对背景的对比度 ≥ **4.5:1**（WCAG AA）。实测基线：正文 `--c-text` 对页面底 ≈12.4:1、对卡片 ≈12.5:1；次要文字 `--c-muted` 对卡片 ≈6.3:1 |
| C2b | **结论标签是 12px 小字，属 WCAG「小文本」，文字对标签底必须 ≥4.5:1**——用「浅底 + 深字」配对（soft/deep 变量），不准用白字压原色底（实测仅 2.35~4.13:1，不达标，Day 12 延伸已修复） |
| C2c | **状态反馈按钮的字（13px，同样属小文本）对按钮底必须 ≥4.5:1**——收藏已收藏/失败、复制成功/失败四个态都用「soft 底 + deep 字 + 同色 1px 描边」（描边负责在浅页面底上保持按钮轮廓），不准白字压原色底（实测 2.35~3.9:1，Day 14 已修复，实测 5.79~6.92:1）。新加反馈态一律照此办理 |
| C3 | 结论四色**严格绑定语义**，不得挪用：假=红、部分属实=橙、真=绿、存疑=紫。原色（`--c-fake` 等）只给大面积色块和状态按钮；标签一律用 soft/deep 配对 |
| C4 | 一眼灰度的中性色（边框、禁用底、hover 底）允许硬编码，但必须保持现有取值并登记在脚本白名单里；新增中性色要先问 |
| C5 | 状态反馈必须「**颜色 + 文案**」双通道，不许只靠颜色区分（色盲用户可用） |

### 字体

| 规则 | 内容 |
|---|---|
| C6 | 字体栈固定 `"Segoe UI", "Microsoft YaHei", sans-serif`，`line-height: 1.6` |
| C7 | 字号阶梯（不得随意新增）：**22** 站名 / **18** 详情标题 / **16** 卡片标题与小节标题 / **14** 次级文字与 tab / **13** 正文辅助、按钮、卡片摘要 / **12** 日期、元信息、最小字号 |
| C8 | 最小字号 12px，正文字号 13px 起 |

## 三、卡片与按钮

来源：Day 8 卡片流、Day 10 空态指路、Day 11 复制与收藏。

### 卡片

| 规则 | 内容 |
|---|---|
| B1 | 卡片统一：`border-radius: var(--radius)`（12px）+ `box-shadow: var(--shadow)`，hover 时上浮 `translateY(-4px)` + `--shadow-hover` |
| B2 | 卡片整体是 `<a>`，点哪儿都能进详情（触控友好）；链接文字色继承正文，不用浏览器默认蓝 |
| B3 | 卡片内文字层级固定：`.card-date`(12) → `.card-title`(16) → `.card-summary`(13) → `.card-meta`(12) |
| B4 | 列表/卡片容器用 `display: flex; flex-direction: column; gap` 排布，**不用固定高度**，高度由内容决定 |

### 按钮

| 规则 | 内容 |
|---|---|
| B5 | 一律「胶囊」形：`border-radius: 20px` + `min-height: 44px` + 横向 padding 18~20px（触控目标下限） |
| B6 | 颜色语义分工：主色 = 主行动（复制结论、空态指路）；灰色 `#e0e3ec` = 次行动（未收藏）；语义色 = 状态反馈（成功用 `--c-true`、失败用 `--c-fake`） |
| B7 | 每个按钮必须有 hover 反馈（至少背景色变化）；全局必须有 `:focus-visible` 焦点环（`outline: 3px solid rgba(59,91,253,.45)`，offset 2px） |
| B8 | 原生 `<button>` 优先，键盘 Tab + Enter 必须能触发，不许用 `<div onclick>` |
| B9 | 需要状态的交互（如收藏）要覆盖：未操作 / 处理中（`disabled` + "xx中…"）/ 成功 / 失败（含"怎么重试"的指引），且失败提示出现时按钮必须已可点 |

### 列表筛选（Day 12 延伸起：三处数据对象统一规范）

| 规则 | 内容 |
|---|---|
| B10 | **四处列表**（辟谣榜、检索页站内结果、论坛帖子、详情页信源）都要有关键词筛选：**输入即过滤**（input 实时过滤，无后端），与该处既有筛选条件（结论 chip / 时间档 / 帖子分类）**叠加**生效 |
| B11 | 无匹配一律显示**「没有找到相关内容」**+ 一个清空出口按钮；清空关键词后恢复当前条件下的完整列表。既有条件也没了时出口语义要跟着变（辟谣榜：仅关键词→「清空关键词」，关键词+结论→「清空全部筛选」；论坛同此规则） |
| B12 | 搜索框统一 `.filter-search`（44px 触控高度 + `aria-label`）；结果计数文案要同时反映结论与关键词两个条件（如「筛选「假」 + 关键词「加油站」：共 1 条」） |

## 四、移动端适配

|---|---|

## 五、视图路由与列表四态（Day 13 起）

来源：Day 13「实现 3 个视图 + 补齐四种状态」。

| 规则 | 内容 |
|---|---|

## 已知边界

- 脚本的对比度计算基于 `:root` 里的变量值，**不解析组件内硬编码的中性色**（那部分由白名单控制）。
- 卡片 hover 动效只能在真实浏览器里测得（依赖 `:hover`），无头模式用强制 hover 模拟。
- 字体渲染、亚像素对齐等视觉细节脚本测不了，仍需人工看一眼截图。
- **hash 路由的地址带 `#`**（`index.html#/board`），不是 `/board` 这种干净路径。这是纯静态托管（GitHub Pages 无重写规则）下的自觉取舍——用 History API 需要 404 回退方案，列入下一步计划，不阻塞当前阶段。
- `?demo=` 演示开关是**临时装置**，上线前必须删（或用构建流程剔除），否则用户能手动把页面强制成错误态。
- **登录、发帖、账号区只能在线上验证**：托管后端的邮箱登录按 Origin 校验，只在发布域名可用（本地预览登不上）。本地能验的是「未登录时的门槛立不立得住」与「面板入口齐不齐」。
