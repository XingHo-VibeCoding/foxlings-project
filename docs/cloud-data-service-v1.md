# 云端数据服务 v1（交付文档 · Day 21 周验证日产出）

> 课程口径（第 3 周原文）：**「产生第三周验收，产出云端数据服务 v1」**；本周产出 = 「一个公网可访问的『云端数据检查台』」。
> 本文档把项目已跑起来的那套托管后端**收成一份可评审、可交付的说明**——不改代码、不新增能力。
> 权威细节以 `api-contract.md`（接口与字段）与 `db/schema.sql`（表结构）为准，本文是它们的**服务级摘要 + 验收证据**。

## 一、这是什么形态的服务

托管后端，**SDK 直连数据库（PostgREST），没有自建 HTTP 服务层**。安全不靠服务端代码，靠数据库自己的三道闸：

```
第 1 道  GRANT      —— 客户端角色对表有没有基本权限（如 items 连 UPDATE 权限都没给）
第 2 道  RLS 策略   —— 有权限也只准动「策略放行的那部分行」
第 3 道  函数窄口   —— 唯一例外：bump_item_view()，SECURITY DEFINER，只放行「+1」
```

前端与云的所有来往都收在四个出入口：`js/api.js`（数据 + 存储）、`js/auth.js`（身份）、`js/ai.js`（LLM），页面脚本不得绕过（frontend-rules A 组硬门槛管着）。

## 二、数据建模：怎么套「主对象 + 时间累积记录」范式

课程给的范式是**「一个主对象 + 一堆时间累积的记录」两张表**（打卡应用示例 `plan_days / checkins`）。本项目的套法：

| 范式角色 | 本项目对应 | 说明 |
|---|---|---|
| 主对象 | `items` 核查条目 | 编辑产出的核查结果，`sources` 用 JSONB 内嵌（每条 2–5 个信源，永远跟条目一起取，不拆表） |
| 时间累积记录 ① | `reports` 用户线索流 | 未登录也可提交，进来进 `pending` 队列，核查成稿后回填 `item_id` |
| 时间累积记录 ② | `posts` 论坛帖流 | 登录用户产生，`item_id` 可关联某条核查 |
| 支撑表 | `profiles` / `admins` | 「我是谁」与「谁能管」，不是业务主对象 |

判断标准那条也照做了：主题不是打卡类，按最接近的结构套用，跑通后再调整——**没有在第 3 周重新设计**。

## 四、权限模型（谁能动什么）

| 角色 | 能做 | 不能做 |
|---|---|---|
| 未登录访客 | 读 items / 已过审 posts；提交匿名线索（落 `'anon'`）；调 `bump_item_view` +1 | 发帖；读任何人提交的线索；读 profiles；碰后台 |
| 登录用户 | 上面全部 + 发帖（强制 `pending`）/ 回读自己的线索 / 读写自己的资料 / 传头像 | 动别人的行；直接插 `approved`；改 `admins` 名单 |
| 管理员（`admins` 表成员） | 后台：读全部帖与线索、审核改状态、删帖、删榜单条目 | 手动改热度/浏览数——**函数参数里没有数字**，「管理员也不能调序」由函数签名保证；改名单（无写策略，加人走 SQL） |

三条平台事实（都实测过，写策略前必须知道）：
1. **未登录 `auth.uid()` 返回 `'anon'`（字符串），不是 NULL** —— 涉权限的策略一律 `TO authenticated`；
2. 匿名 INSERT 不能带 `.select()`（无 SELECT 权限，`RETURNING` 会整体失败）；
3. 管理策略统一 `EXISTS (SELECT 1 FROM admins a WHERE a.user_id = auth.uid())`，权限真身在库，改前端解锁不了任何操作。

## 五、接口契约摘要

完整定义（字段、约束、错误码、分层规则）见 `api-contract.md` 第一、二节，此处只列服务级视图：

| 能力 | 前端入口 | 后端形态 |
|---|---|---|
| 条目列表 / 详情 | `api.getItems()` | SDK 直连 `items`（公开只读） |
| 浏览计数 +1 | `api.bumpItemView(id)` | rpc → `bump_item_view`（窄接口，只能 +1） |
| 论坛读 / 发帖 | `api.getPosts()` / `api.createPost()` | SDK 直连 `posts`（RLS 过滤 + 强制 pending） |
| 线索提交 / 回读 | `api.submitReport()` / `api.getMyReports()` | SDK 直连 `reports`（匿名可写不可读） |
| 资料 / 头像 | `api.saveProfile()` / `api.uploadAvatar()` 等 | `profiles` 表 + 云存储 `shared/` |
| 管理后台 | `admin.html` + 7 个 `api.*Admin*` 方法 | 6 条 `*_admin_*` 策略逐请求再核 |
| AI 整合 | `ai.digest()` | SDK 直连 LLM（不判真伪写死在系统提示词） |
| 榜单排序 | `js/home.js` | **前端算**：`(heat + views) × 0.5^(天数/14)`——排序公式属展示层，不占服务 |

## 七、v1 已知边界（如实交底，v2 候选）

| # | 边界 | 现状与代价 |
|---|---|---|
| 1 | L3「自动联网」做不了 | 托管后端无搜索/抓取通道；已按拍板降级为「AI 拆解 + 指路」，溯源仍是人工入口 |
| 2 | 邮箱登录只在发布域名可用 | 平台按 Origin 校验；本地只能验未登录态 |
| 3 | 频控缺失 ×2 | 匿名线索提交、头像上传均无频控/体积上限（RLS 管「谁」不管「多快」）；前端 2MB 只是可用性提示 |
| 4 | 浏览量去重是本机的 | localStorage 挡同设备刷新；换浏览器/清缓存会重复计，当前规模（个位数）接受 |
| 5 | 签名 URL 不续签 | 挂超 1 小时头像裂图，重渲染即恢复 |
| 6 | 检索无中文分词 | `pg_trgm` 扩展托管环境未启用，站内检索用 ILIKE 兜底（≤2000 条够用） |
| 7 | `posts.replies` 是展示预留 | 回复表未建，暂由种子填值 |
| 8 | 演示开关未拆 | `?demo=` 保留至真人测试结束再删 |
