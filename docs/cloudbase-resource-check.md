## 任务 A｜看当前用量（四条通道，逐条查）

### A1 数据库行数与内容指纹（命令行，最硬的一条）

```bash
cd D:\AI\foxlings-project
node tools/check-data-counts.js --tag <本次标签> --out <仓库外目录>\<文件名>.json
```

- 用 `Prefer: count=exact` 拿**库里总数**（不是"取回多少行"），所以不会被 1000 行上限骗。
- 输出形如 `items HTTP 200 行数 23/23 views 合计 69 指纹 ba05d5f5…`。
- 指纹**已排除 `views` 列**（访客点详情页会让 views 涨，那是真实业务写入，算进去就是自造假警报）。
- ⚠️ 快照文件**必须写到仓库外**（仓库目录会随发布公开）。

### A2 表清单 / 结构

- 表清单：云服务端点 + `/.cloud/database/rest/` 逐表探活，或走云服务的表列表接口。
- 结构以仓库内 `db/schema.sql` 为唯一真相。**改了云端结构必须同步它。**
- 判据红线：**表在 ≠ 可读。** 只有 `HTTP 404 + PGRST205` 才算"表丢了"；`401` 是被 RLS 挡、`200 + 空数组` 是"读到了但可能全被挡光"，两者都不能判成空表。

### A3 账号与存储（用云服务的只读接口）

| 想看什么 | 怎么做 | 本次实测（2026-10-16） |
|---|---|---|
| 终端用户数 | 云服务的「列出终端用户」（只读，传 applicationId） | **1**（邮箱注册，创建于 2026-10-08） |
| 存储对象 | 云服务的「列出对象」，根目录传空串 | **2 个虚拟根**：`users/`、`shared/`（均为空） |

### A4 可用模型目录

- 云服务的「列出模型」，传 applicationId → 返回模型 ID / 上下文窗口 / 能力标识。
- 本次实测：**32 个模型可用**。
- 注意：`credits` 字段（如 `x0.29`）是**计费倍率的展示文案，不是余额**，别当额度读。

### A5 环境健康度（代替"到期时间"的两个可用信号）

云服务的环境信息里看这两条，它们是**当前唯一能机器读取的健康信号**：

- `billingStatus` —— 计费状态，`normal` = 正常
- `provisionStatus` —— 资源开通状态，`assigned` = 已绑定

本次实测：**`billingStatus=normal`、`provisionStatus=assigned`** → 无需任何续期动作。

## 任务 B｜看到期时间（诚实版：目前没有工具能读到）

**先说结论**：截至 2026-10-16，**没有任何工具接口能读出"到期日期 / 剩余额度 / 计费周期"**。
（`credits` 字段只是展示文案；云服务的只读接口里也没有额度余额这一项。）

所以到期时间只能**到控制台用眼睛看**，步骤如下：

1. 打开 WorkBuddy 客户端 → **设置** → **数据管理** → **云服务**。
2. 选中应用「时事真伪辨别」（ID 尾号 `…to06`）。
3. 在应用详情/资源页里找：**有效期 / 到期时间 / 套餐与用量** 一栏，把看到的**日期**和**套餐名**抄下来。
4. 若页面上有「用量」图表，记录：数据库存储量、函数调用次数、AI 用量（如果有）。
5. **把抄到的值填进 `docs/resources-and-expiry.md` 的「到期与套餐」小节，并注明"人工读取，非接口"**。

> ⚠️ 菜单路径随客户端版本会变。**以你当前客户端实际显示为准**；找不到就在设置里搜"云"。
> ⚠️ 抄的时候**只抄日期和套餐名**，页面上任何密钥/凭据一律不抄、不截图外传。

**如果连控制台也找不到到期时间**：在说明文档里如实写"本次未能读到"，**不要用估算值填空**——填了假数字，下次复测的人会以为那是真的。

## 任务 C｜导出数据（两种方式，用途不同）

### C1 命令行导出（推荐，可复现、有覆盖度记录）

```bash
cd D:\AI\foxlings-project
node db/export-data.js --out <仓库外目录>\backup-YYYY-MM-DD
```

- ⚠️ **备份目录必须在仓库外**——脚本会拒绝写在仓库内（发布会把整个项目目录公开）。
- 产物目录里有一个 `manifest.json`，写明每张表的覆盖程度：`full` / `partial` / `unknown` / `denied`。
  **以 manifest 为准，不要凭"导出没报错"就当成全量备份成功。**

### C2 已知的能力边界（硬事实，写进说明文档别漏）

| 表 | 匿名身份能导出吗 | 说明 |
|---|---|---|
| `items` | ✅ 能 | 内容主体 |
| `posts` | ✅ 能 | 论坛帖 |
| `announcements` | ✅ 能 | 公告 |
| `reports` | ❌ 401 读不到 | 用户提交的线索，**当前不可备份** |
| `profiles` / `admins` | ⚠️ 回 200 + 空数组 | RLS 全挡光与"真的是空表"长得一模一样，**判不出**，标 `unknown` |

→ 这三张表一旦误删，**当前不可恢复**。这是已知的、写在文档里的缺口，不是导出脚本的 bug。

### C3 恢复（只生成 SQL，不自动执行）

```bash
node db/restore-from-backup.js --from <备份目录>
```

- 只生成 `restore.sql`：`INSERT ... ON CONFLICT DO NOTHING`（不会覆盖现有数据）。
- identity 列（`posts`/`announcements`/`reports` 的 `id`）会自动加 `OVERRIDING SYSTEM VALUE` 并补 `setval`——漏了会报 `428C9`。
- **生成后要人工在 SQL 通道执行**，脚本不代执行。
