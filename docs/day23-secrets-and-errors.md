### 1.2 唯一命中项的定性：`publishableKey`

`js/cloud-config.js:19` 命中了我自己加的 `wbpk_` 模式。**它没有被藏起来，也没有被删掉** —— 理由是它是设计上公开的标识符，藏起来是自欺欺人（浏览器里本来就看得见）。

但「我认为它公开无害」不等于「它真的无害」。所以做了实测（2026-10-11，裸通道只带这个 key）：

| 拿它去做什么 | 结果 |
|---|---|
| 读公开条目 `GET /items` | 200（设计如此，所有人都能读） |
| **改热度** `PATCH /items` | **401 `DATABASE_42501` permission denied** |
| **删条目** `DELETE /items` | **401 permission denied** |
| **读别人提交的线索** `GET /reports` | **401 permission denied** |
| **读站方名单** `GET /admins` | 200 `[]` ← 见下 |

`admins` 那条返回的是 `200 []` 而不是 401，**这个差别必须说清**：401 是「明确拒绝」，200 是「允许你查了，只是没查到」——后者更容易被误当成漏洞。查了策略定义才定性：

```
表 admins：relrowsecurity = true
策略 admins_read_self：FOR SELECT TO authenticated USING (user_id = auth.uid())
```

即**只授给登录用户，且只能看到自己那一行**；匿名不匹配任何策略 → 行被过滤成空集。用角色模拟做了正反对照：

- 管理员本人查 → **1 行**
- 非名单用户查 → **0 行**

结论：拿到这个 key 只能做「所有人本来就能做的事」。六张表 **RLS 全部开启**。

## 二、`.env` 与忽略规则（含 2026-10-11 新增的 `.env.example`）

### 2.1 忽略规则是否**真的**生效

`.gitignore` 覆盖 `.env` / `.env.*` / `*.pem` / `*.key` / `id_rsa*`。

关键区别：**「写了规则」和「规则生效」是两件事**。用 `git check-ignore -v` 逐条验证，四条都命中并给出了命中的规则行号；同时确认 `git ls-files` 里没有任何被跟踪的配置类文件。

另外补一条历史检查：**规则是今天才生效还是从来如此**——`git log --all` 覆盖全部历史与分支，没有任何提交添加过这类文件。（如果历史上提交过，光删文件是不够的，历史里还留着。）

### 2.2 新增 `.env.example`：仓库里放**不含真值**的样板

规矩一句话：**样板里永远不许出现真实值** —— 真值一旦出现在这里，就等于进了仓库、进了 git 历史，删掉也没用。

`.env.example` 把变量分成两组，分组本身就是这条边界：

| 组 | 变量 | 能不能进前端 | 为什么 |
|---|---|---|---|
| A · 前端可见 | `WB_SITE_ORIGIN` / `WB_ENDPOINT` / `WB_PUBLISHABLE_KEY` | ✅ | 公开标识，浏览器里本来就看得见（§1.2 已实测无权限） |
| B · 只在服务端 | `DATABASE_URL` / `SERVICE_ROLE_KEY` / `LLM_API_KEY` | ❌ **绝不** | 拿到就能用；本项目里它们由托管平台持有，前端够不到 |

### 2.3 「统一走环境变量」在**静态站**上怎么落地（如实说明）

本项目是「静态前端 + 托管后端」，**没有构建步骤** —— 没有 webpack/vite 那种在打包时注入 `import.meta.env` 的机会。
所以这条要求落地成一条可执行的链路，而不是一句口号：

```
.env（人写的真值，已忽略）
   │  node env-to-js.js      ← 只转「组 A」，组 B 主动跳过并提示
   ▼
js/env.local.js（已忽略）→ window.__ENV__
   │
   ▼
js/cloud-config.js          ← 优先读 window.__ENV__；没有就回落到文件里的默认值（= 线上那一套）
```

三件事让这条链路不是摆设：

1. **不配也能跑**：`cloud-config.js` 里有默认值，本地什么都不准备照样打开页面。
2. **凭据进不了浏览器是脚本保证的**：`env-to-js.js` 的白名单里只有组 A —— `.env` 里就算写了
   `DATABASE_URL`，它也不会被写进 `js/env.local.js`。这条边界**不靠人记得**。
3. **配置坏了不静默**：`WB_ENDPOINT` 认不出是网址时，回退到默认值并把原因写进 `console.error`，
   而不是让后面每一个请求都报一个看不懂的错。

### 2.4 一个必须一起改的**自相矛盾**

加这个文件时撞上两处「文档说一套、脚本判一套」：

- `.gitignore` 里的 `.env.*` 会把 `.env.example` **一起忽略掉** —— 于是「仓库里放样板」这条要求
  在规则层面直接落空（文件在本地存在，却永远提交不上去）。修法：紧随其后加 `!.env.example`。
- `check-secrets.js` 的「配置类文件进了仓库」那条规则用 `/(^|\/)\.env/` 匹配，同样会误伤 `.env.example`。
  修法：把 `.example` 后缀从这条规则里放行 —— **但同时把它加进扫描扩展名**，
  因为样板恰恰是最需要被红线扫的地方（有人往里粘真值，必须当场抓到）。

顺带把「样板里没有真值」变成机器可验的第 4 组检查：拿 `js/cloud-config.js` 里的**线上真值**当场比对，
再要求非空的值必须「看得出是占位符」（含 `your` / `example` / `replace` 等），并确认 `.gitignore` 里有 `!.env.example`。

## 三、三类错误提示统一

### 3.1 三类是怎么分的

按「错误发生在哪一段路上」分 —— 这个分法的好处是**用户能据此知道下一步该干什么**：

| 类 | 发生在哪 | 用户该做什么 |
|---|---|---|
| ① 网络类 | 请求还没到服务器（断网 / 被跨域拦 / SDK 没加载） | 检查网络、用发布地址重试 |
| ② 权限类 | 到了，但身份不够（没登录 / 不是管理员 / RLS 拒绝） | 登录、或换有权限的账号 |
| ③ 数据类 | 身份够，但数据不对（不存在 / 格式不符 / 重复 / 类型不对） | 改内容、或确认这条还在不在 |

### 3.2 改前 → 改后（现场实测对照）

左边是服务端吐的原文，右边是用户实际看到的那句话。三条都在真实页面 + 真实服务端上打出来的：

| 类 | 服务端原文 | 界面显示 |
|---|---|---|
| ① 数据类 | `HTTP 400 {"code":"DATABASE_23514","message":"new row for relation \"reports\" violates check constraint \"reports_text_check\""}` | **内容不符合格式要求（标题或正文长度不对）。** |
| ② 权限类 | `HTTP 401 {"code":"DATABASE_42501","message":"permission denied for table announcements"}` | **这条操作没有被允许——如果是在发帖，请先登录再试。** |
| ③ 网络类 | `TypeError: Failed to fetch` | **网络没连上——检查下网络，或者用发布地址重试。** |

**今天真正改掉的那一句裸报错**：`TypeError: Failed to fetch`。它是浏览器在连不上时抛的，SDK 有时包一层、有时不包 —— 原来会原样出现在界面上。

### 3.3 收口在哪：一处判断，四个映射函数

**没有逐处打补丁**，而是在 `js/api.js` 顶部立了一节「三类错误提示的统一口径」，把网络的认法与话术收成唯一来源：

```js
const NET_ERROR_RE  = /failed to fetch|load failed|network\s?error|.../i;
const NET_ERROR_TEXT = "网络没连上——检查下网络，或者用发布地址重试。";
function isNetworkError(err) { ... }
function userFacingFallback(raw, fallback) { ... }   // 含中文的原文透传，英文换成中文
```

四个映射函数全部改为调用它：`describeError`（api.js）、`describeStorageError`（api.js）、`describeAiError`（ai.js）、`authErrorText`（auth.js）。
页面层那约 20 处 `err.message || "兜底"` **一行都没动** —— 因为上游保证了一定是中文，这正是「收口」而不是「打补丁」的意义。

**两条纪律**（写进代码注释）：

1. 界面上的每一句都必须是中文 —— **英文原文只进 console**（那里有完整日志可查）。
2. 兜底宁可说「操作失败，请重试」，也不拼一段英文出去。「看不懂的报错」比「说得笼统的报错」更伤：前者用户只能截图来问，后者至少知道下一步干什么。

**为什么 AI 与数据库两条路原来都没认断网**：之前只有云存储那条 `describeStorageError` 里写了一次「failed to fetch」的正则，另外两个没有 —— 于是断网时提交线索会吐 `提交线索失败：Failed to fetch`。认法散在三个地方，漏一个就漏一类，所以必须收成一处。

### 3.4 验证

**① 单测 23 条断言，全过**（`verify/test-day23-errors.js`）

网络 8 条 / 权限 4 条 / 数据 5 条 / 兜底 5 条 / **总断言 1 条**。

总断言是整件事的核心：**所有输出里不允许出现英文单词** —— 结果 **0 条泄漏**。
（另有一条容易被忽略的：服务端已经翻好的中文兜底要**照原样透传**，不能因为「要统一」就把有用的话也盖掉。）

**② 现场取证**（`verify/probe-day23-errors.js`）

三条都在真实页面上触发、同上表：数据类与权限类**真的打到了数据库**（被 CHECK 约束与 RLS 分别拒绝），网络类靠拦掉请求复现。整个过程**未捕获任何 JS 异常**。

### 3.5 测试脚手架说明（如实记）

本地页面的 origin 不在服务端白名单里，直连云服务会被 CORS 拦。所以取证脚本把 `/.cloud/**` 的请求**真转发**到线上并在响应上补 CORS 头 —— 请求本身是真发出的，只是绕开了浏览器的同源检查。**这是测试脚手架，未改动任何被测代码。**

另外本机访问 `cdn.jsdelivr.net` 被重置（`ERR_CONNECTION_RESET`，Node 直连也失败），脚本改用工作区里存下的同一份 SDK 供应，否则页面里 `window.WorkBuddyCloud` 是 undefined，根本测不到今天的改动。**访客网络不受此影响**（线上页面照常加载 CDN）。

### 3.6 顺手修正的一处**不准确**的文案

数据类里 `23514` 原来写的是「内容不符合格式要求（**标题或正文长度不对**）」。
但 `23514` 是 PostgreSQL 的「CHECK 约束被违反」——**长度越界和枚举非法都走这个码**
（`category` 不在三项之内、`verdict` 非法同样是 23514）。于是那句话会对一个选错分类的用户说
「你的标题或正文长度不对」，把人指到错的地方去了。

改成：「内容不符合格式要求（**长度或选项不在允许范围内**）」。

（单测里那条断言只比对了前缀「内容不符合格式要求」，所以这次改写**没有削弱任何断言** —— 23 条仍然全过。）

## 四、输入边界：哪些输入接受、哪些拒绝

### 4.1 这条边界的规矩：两端同一个数字

「能跑的代码」和「能上线的代码」在这里的差别是：**输入有没有被真正界定过**。

- **数据库 CHECK 是真相**。浏览器能被绕过、脚本能直接 POST —— 只写前端校验等于没设防。
- **前端 JS + `maxlength` 只是早提示**：让人在**点提交之前**就知道，而不是先放行、再收到一句拒绝。

最容易坏的方式不是「没人写」，而是**两端各写一个数字，改了一边忘了另一边**：
数据库还是 5–500，前端某天被改成 3–800 —— 用户看到「可以提交」，点下去却收到一个看不懂的拒绝。
**这种坏没有信号**：不报错、不崩、测试也过，只有真人踩到才知道。

### 4.2 本次审计补上的三处真缺口

| 缺口 | 原来是怎么样 | 现在 |
|---|---|---|
| 线索输入框没有 `maxlength` | `mine.html` 的 `#rep-input` **没有任何长度属性**，只在点「提交线索」时用 JS 拦 500 字 | 加上 `maxlength="500"`，边打字边被框住 |
| 公告排序权重无上下限 | `type="number"` 无 `min`/`max`；JS 写的是 `Number(v) \|\| 0` —— 输 `abc`、`Infinity` 会**静默变成 0**，公告落到谁也没选过的位置，毫无信号 | JS 明确拒绝非整数 / 越界并说明区间；输入框加 `min/max`；数据库补 `CHECK (sort_order BETWEEN -9999 AND 9999)` |
| `reports.url` 没有上限 | 这一列**匿名访客可以直接 POST**，却没有任何长度约束 —— 等于在站方待审队列上留一个「塞进任意长字符串」的口子 | 数据库补 `CHECK (url IS NULL OR char_length(url) <= 500)`（UI 暂不采集，上限由数据库兜底） |

### 4.3 固化成机器校验：`check-boundaries.js`

边界表不只写在文档里 —— 仓库根目录新增 `check-boundaries.js`：

- **锚点（真值来源）= 数据库 CHECK**；不落库的（AI 拆解输入）锚点是前端常量。
- **跟随者 = 前端 JS 校验 + 输入框 `maxlength`**，必须与锚点一致。
- **脚本自身不持有任何边界数字** —— 它从代码里**读出来**比对（若在脚本里再抄一份，就变成 4 份，谁也不知哪份是真的）。
- 规则**没找到**也算失败：代码改了、扫描规则没跟上，本身就是规则腐坏。
- 长度区间之外，还验三类**枚举**三方一致（`posts.category` / `items.verdict` / `items.cross_check`）。

当前覆盖 11 组长度边界 + 3 组枚举，**全部一致**（含数据库这端的实测，见下）。

### 4.4 证明它不是橡皮图章（反例靶子）

一个只会说 PASS 的校验脚本没有价值。所以把仓库**复制一份到临时目录**，故意改坏三处
（`js/mine.js` 上限 500→501、`admin.html` 公告标题 `maxlength` 60→50、`js/forum.js` 分类少一个值），再跑：

```
[基线] 未改动 → 退出码 0（PASS）
[漂移后] 退出码 1
   前端 JS 上限      js/mine.js    ❌ max 期望 500、实际 501
   输入框 maxlength  admin.html    ❌ max 期望 60、实际 50
   前端常量 POST_CATS js/forum.js  ❌ 期望 已解决 | 求助溯源 | 经验讨论、实际 已解决 | 求助溯源
   结论：FAIL —— 3 处对不上
```

三处全部被点名，真仓库一个字节没动，临时副本跑完即删（`verify/probe-day23-boundary-drift.js`）。

### 4.5 数据库那端也实测过（不是只看 DDL）

加约束之前先查过存量数据不会违规（违规行数 0），加完再用**必然违规**的写入打正对照：

| 写入 | 结果 |
|---|---|
| `sort_order = 100000` | 23514 拒绝 ✅ |
| `sort_order = -100000` | 23514 拒绝 ✅ |
| `url` 长度 600 | 23514 拒绝 ✅ |
| `sort_order = 9999` / `-9999`（边界值） | 放行 ✅ |
| `url` 长度恰好 500（边界值） | 放行 ✅ |

> 于是插入先撞上 `author_id` 非空约束（23502），**根本没走到 sort_order 的检查** ——
> 差点就得到「约束没问题」的假结论。补上 `author_id` 重测才拿到真结果。

   ⚠️ 注意：`js/*.js` 与 `*.html` 的改动意味着**线上与本地不再逐文件一致**，发布时要照例逐文件 md5 复核。
4. **豁免是「有依据的例外」，不是「看不见」**：`publishableKey` 依然在源码里，依然会被扫描器命中。`check-secrets.js` 每次都会把它列出来 —— 让它保持显眼，比让它消失更安全。
5. **`.env` 这条链路是「备好但还没被实战检验」的**：目前只有一个线上环境，所以平时并不存在 `js/env.local.js`，
   页面上跑的就是 `cloud-config.js` 里的默认值。这条链路真正的用途是「将来本地要连另一个环境」——
   到那天它才会第一次被真用。**不要把「写好了」当成「验过了」。**
6. **`check-boundaries.js` 只能验证「已登记」的边界**：新加一个输入面却忘了往登记表里加一条，它不会发现。
   所以「新增任何输入面」= 必改登记表（这条比脚本本身更容易被忘）。另外它只覆盖**长度 / 区间 / 枚举**
   这三类能用正则读出来的约束；**结构性**的边界（如「发帖时 `author_id` / `status` 不许客户端传」）
   由 RLS 的 `WITH CHECK` 管、由单测管，不在这张表里。
7. **`reports.url` 仍无 UI 入口**：上限只由数据库兜底。将来加「附上原始链接」输入框时，
   要同时补前端校验**并往登记表里加跟随者**（否则本节第 6 条就会应验）。
