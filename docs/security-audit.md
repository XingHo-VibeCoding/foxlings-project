# 错误处理与安全审计（Day 25 · 2026-10-11）

> 这份文档回答三个问题：**发现了什么 → 怎么修的 → 以后怎么知道它没退化**。
> 第三部分的自查清单里，**每一项都写了「怎么算通过」**（可复现的命令或操作步骤），
> 不写「已修复」——那句话谁都能写，但它挡不住下一次改动。

## 零、这次审计怎么做的

| 项 | 说明 |
|---|---|
| 扫描范围 | 仓库全部文本文件（`js/*.js`、4 个 html、`css/`、`db/`、`docs/`、`data/`、根目录脚本）= 50 个文件 |
| 口径一：什么算「硬编码密钥」 | 拿到就能用的东西：私钥块、云厂商 AccessKey、平台 Token、**带账号密码的连接串**、JWT 实串、`service_role` 这类服务端密钥字段、硬编码口令 |
| 口径二：什么算「未处理的错误路径」 | 三条：① 报错**直接甩给用户**（英文/技术栈）② 报错被**静默吞掉**（用户看到的是「空的」而不是「失败的」）③ **没有任何人接**（漏网的异步异常，界面毫无反应） |

**为什么要写成脚本**：手工搜一次没有意义 —— 下次没人记得该搜哪些词、该排除哪些文件。

## 一、审计：问题清单

### 1.1 硬编码密钥 / 连接串 / API Key

| # | 位置 | 内容 | 判定 | 依据 |
|---|---|---|---|---|
| A1 | `js/cloud-config.js:29-30` | 线上 `endpoint` + `publishableKey`（`wbpk_…`） | **保留**（设计如此） | 见下 |
| A2 | `check-secrets.js` 豁免名单 | 只豁免 `wbpk_` 形态的**值**（非整个文件） | 通过 | 豁免范围是值不是文件，别的密钥写进同一文件照样会被红线抓到 |
| A3 | `.env.example` / `.gitignore` / `env-to-js.js` | 三件套齐全 | **通过，但从未实战跑过** → 本次补测 | 见 §2.1 |
| A4 | git 全历史 | `.env` / `.env.*` / `*.pem` / `*.key` | **从未提交过** | `git log --all --diff-filter=A` 里 `.env*` 为空 |
| A5 | 全仓红线扫描 | 私钥块 / AKIA / gh[pousr]_ / sk- / xox / AIza / 连接串 / JWT / 服务端密钥字段 / 口令 | **0 条** | `node check-secrets.js` |
| A6 | 数据库连接串 / 服务端密钥 / LLM Key | 前端与仓库里**根本不存在** | 通过 | 本项目走托管后端：连接串只活在平台执行通道里，LLM 走平台免密钥通道（没有 API Key 可填） |

**A1 为什么不算缺陷**（不是「看着不像密钥」，是三条证据）：

1. 本项目是**静态站、没有构建步骤** —— 「环境变量」的落点只能是页面里的 `window.__ENV__`。
   `DEFAULTS` 的作用是「什么都没配也能跑」，不是「藏一个密钥」。
2. 优先级是 `window.__ENV__ → DEFAULTS`，也就是说它可以被 `.env` 整体覆盖（本次已实测，见 §2.1）。
3. `publishableKey` 是**设计上公开的标识**，且这一点靠**实测**而不是靠声明：
   拿它走裸通道越权 —— 读公开条目 `200`｜改热度 `401`｜删条目 `401`｜读他人线索 `401`。
   但它**不能**因此就说「所有 wbpk_ 都无害」—— 所以 `check-secrets.js` 把它**单列成一组**
   （「命中了哪几处 + 为什么放行」写在输出里），而不是静默忽略。

### 1.2 未处理的错误路径

| # | 位置 | 原来会怎样 | 为什么算问题 |
|---|---|---|---|
| **B1** | 全局（原来**没有**任何 `unhandledrejection` / `window.onerror`） | 漏网的异步异常 = 界面**毫无反应** | 用户在页面上能看到的只有「点了没反应」；这类「静默失败」是最难查的 bug，且这类异常**不会走任何 catch** |
| **B2** | `js/admin.js` 的 `safe()`（4 处） | 读失败 → `console.error` → 返回 `[]` | 后台把「**读不出来**」显示成「**库里没有**」。管理员会据此以为数据丢了，然后做没必要甚至有害的操作 |
| **B3** | `js/mine.js` `refreshReports` | 读失败 → 静默 → 渲染「还没有提交过线索。」 | 用户会以为**自己提交的线索丢了** |
| **B4** | `js/forum.js` `refreshPosts` | 读失败 → 静默 `return` | 刚发完帖/刚点刷新，界面一点变化都没有 —— 最容易被理解成「按钮坏了」 |
| **B5** | `js/api.js` `getCloudClient()` | 配置没加载时抛 `TypeError: Cannot read properties of undefined (reading 'endpoint')` | **英文技术栈直接进界面**；而且它发生在所有请求之前，后面每一个请求都会各报一次看不懂的错 |
| **B6** | `js/detail.js:312` | 错误文案「可能是网络抖动或 **data.json 缺失**」 | 文案是 Day 20 之前的 —— 数据源早已是云库。照着它排错只会把人带偏 |
| **B7** | `js/data.js:83` | `renderListState` 的默认错误文案同样写着「**data.json** 没能读到」 | 同上，且它是**全站四态错误态**的默认出口，影响面更大 |
| **B8** | `js/search.js:297` | `"提交失败：" + (e.message \|\| "稍后再试。")` | 全站唯一一处**没过** `userFacingFallback` 的 catch —— 纪律上是个口子（上游目前恰好都是中文，所以没炸） |
| **B9** | 错误分类 | 只有「网络 / 权限 / 数据」三类（说明**错在哪**），没有「**该谁动手**」这一维；服务端错也没有可捞的日志行 | 用户最需要知道的是「我要不要动」；另外排查时没法一眼捞出「用户改不了的那一类」 |

### 1.3 非法输入

| # | 输入面 | 缺口 | 后果 |
|---|---|---|---|
| **C1** | 发帖昵称 `posts.author_name` | 前端只有「非空」+ `maxlength=20`，**缺 JS 长度校验** | 超 20 字要一路撞到数据库 CHECK，用户拿到的是 **23514 泛化提示**（「长度或选项不在允许范围内」），不知道说的是哪一格 |

### 1.4 明确「没有发现」的面（附依据，不是「感觉没问题」）

| 面 | 结论 | 依据 |
|---|---|---|
| **SQL / 查询串注入** | **0 处** | 全站没有一处把用户输入拼进查询：`grep` `.or(`/`.ilike(`/`.like(`/`.filter(`/`.match(`/`.in(`/`textSearch` 无业务用法（命中的全是 `Array.prototype.filter`）；带 `${}` 插值的模板串里出现 `database` / `.from(` / `.select(` / `.eq(` / `rpc(` 的 —— **0 处**。所有数据访问都是 `.from(表).select()/.insert()/.update()/.delete().eq("id", id)` 与 `database.rpc("bump_item_view", { p_id: id })`：**值走参数化通道，不参与查询语法**。检索与筛选全在客户端对**已取回的数组**做 `indexOf` |
| **XSS（存储型）** | **0 处** | 所有用户可控文本进 `innerHTML` 前都过 `escHtml`（转义 `& < > " '` 五个字符）：帖子标题/正文/昵称、公告标题/正文、线索正文、个人资料、头像 URL、检索词。AI 输出走 `textContent`（模型输出属不可信内容）。逐点核查见 §3 的 X2 |
| **越权读写** | 靠 RLS，不靠前端 | 前端代码谁都能改、能绕，但绕不过服务端策略：`items` 只有公开读（**零 UPDATE 策略**，热度不可篡改）；`posts` 插入只给已登录且只能插「自己的 + 待审」；`reports` 匿名只能单向写入、读只给已登录看自己；六条 `*_admin_*` 策略只认 `admins` 名单 |
| **密钥泄漏到浏览器** | 组 B 凭据进不去 | `env-to-js.js` 用**白名单**只转组 A（`WB_*`）；组 B（`DATABASE_URL` / `SERVICE_ROLE_KEY` / `LLM_API_KEY`）主动跳过 —— 写进 `js/env.local.js` 的键一定会被页面读到，所以拦在生成环节比靠人记得可靠 |

链路与规矩：

```
.env（人写真值，已忽略）──env-to-js.js──▶ js/env.local.js（页面读的 window.__ENV__，已忽略）
                                                    │
```

  ③ 值要「看得出是占位符」 ④ `.gitignore` 里有 `!.env.example`。**样板本身也在红线扫描范围内。**
- 本次新增实测（`verify/probe-day25-env-chain.js`，10 项全过）：造一个临时 `.env`（组 A 3 个键 + 组 B 3 个**假**凭据）

  → 顺手验「配了非法网址会回退到默认值并写 console」 → **清场（临时文件全删，已核验）**。

> 这一步的意义：把「备好了」变成「跑过了」。之前这条链路是**悬案**（建好了但没拿真值走过一遍）。

## 四、已知边界与未解决项（诚实清单）

1. **G1/G2 的浏览器部分本次没能完整复跑。** 原因：本机访问 `cdn.jsdelivr.net` 被重置
   （`ECONNRESET`，Node 与浏览器都复现），页面的云服务 SDK 加载不到 → 首页渲染不出卡片 → 门槛脚本等
   `#board-list .card` 超时。**这不是本次改动造成的**（同一次会话早些时候该脚本完整跑通过，
   唯一失败的 H2 与 CDN 无关，已修掉并单独复核）。作为补偿，本次新增了三套**离线**探针
   （`82 + 10 + 9 = 101` 条断言：三类错误归属 / 环境变量链路 / 未捕获异常兜底），
   把「不依赖 CDN 就能验的那部分」都固定下来了。
2. **「记录日志」目前是浏览器 console。** 本项目没有自建服务层，也没有日志收集通道，
   所以服务端错的「日志」= 一行可 grep 的 `[api][server-error]` + 完整错误对象。
   **要真正落到服务端，得等有服务层的那天** —— 现在写「已上报服务端」是假话。
3. **`check-boundaries.js` 只验已登记的边界。** 新增输入面忘了登记，它不会响（口径见 I2）。
4. **本机验不了「真实访客 IP」。** 平台把「本机 → 平台域名」的流量走了自己的客户端通道，
   出口 IP 每次都变（连交 6 条落了 6 个不同 IP）→ 提交频控里「匿名按 IP 计」这条
   **只能等真机试用那天核对**（库里看 `reports.submitter_ip` 分布是否符合预期）。
5. **`publishableKey` 仍是可公开的例外**，靠「实测无权限」而不是「类型上无法滥用」支撑。
   一旦哪天平台改了它的语义（比如它能读别人数据），K6 的判据会失效 —— 所以 K6 要求**实测**、不要求「声明」。
6. **本机 `node` 起不了子进程**（`spawnSync` → `EBUSY`），`check-secrets.js` 因此会自动退化为
   「目录递归」口径（比 git 口径更保守：未提交的新文件也扫）。换台机器有 git 时会自动走 git 口径，
   两次口径下结论一致（本次均 PASS）。
