## 二、第一个卡点（20:06 实测，修复前）

陌生人打开网站的第一站就是**整站空白**：

| 视角 | 实测 |
|---|---|
| 首屏卡片 | **0 张** |

| 检索 | 「站内核查库未就绪」 |
| 论坛 | 「帖子列表未就绪」 |

**根因**：4 个页面硬依赖 `cdn.jsdelivr.net` 的 SDK，仓库内无兜底副本。该域名一不可达，整站对访客就是「加载失败」。

**更糟的是它在甩锅**：空态文案写「可能是网络不通，或数据服务暂时不可用」——
真相是**本站自己引的第三方 CDN 挂了**，却引导用户怀疑自家网络，然后关掉页面。
这句话就是我「从没想过的地方」：**写文案的人下意识把「请求失败」都归因于用户的网络或远端服务，独独没想到是自己引的依赖断了。**

## 三、修复（两处，同一问题的两面）

### 3.1 SDK 多来源兜底（治本）

四个页面的 SDK 改为按序兜底，**第一个成功即停**（不再多下）：

```html
<script src="https://cdn.jsdelivr.net/npm/@tencent-ai/workbuddy-cloud-sdk@dev/lib/index.global.js"></script>
<script>window.WorkBuddyCloud||document.write('<script src="https://fastly.jsdelivr.net/npm/@tencent-ai/workbuddy-cloud-sdk@dev/lib/index.global.js"><\/script>');</script>
<script>window.WorkBuddyCloud||document.write('<script src="https://unpkg.com/@tencent-ai/workbuddy-cloud-sdk@dev/lib/index.global.js"><\/script>');</script>
```

用 `document.write` 是**刻意的**：它同步阻塞在 HTML 解析期，保证后面 `js/api.js` 等业务脚本执行时 SDK 一定已就绪（或三个都失败后明确报错），不需要把整个启动链改成 async。
`document.write` 只在解析期同步使用，这是标准 CDN fallback 模式；若放在异步脚本里用会被浏览器忽略——这也是为何它必须紧跟在业务脚本之前的原位置。

### 3.2 错误文案不再甩锅（治标 + 诚实）

四处文案改动（同一口径：**不归咎用户网络，明确「是本站的问题」**）：

| 位置 | 原句 | 改为 |
|---|---|---|
| `js/api.js` getCloudClient | 云服务 SDK 未加载（CDN 脚本没读到，或网络不通） | **本站的数据模块没能加载（已尝试多个来源都不可达）。这是站点自己的问题，不是你的网络**——…（补 code `SDK_NOT_LOADED`） |
| `js/data.js` 空态默认 | 可能是网络不通，或数据服务暂时不可用——过一会儿点「重试」。 | 没能读到数据。可能是网络波动，也可能是本站依赖的服务没起来——**不是你的操作有问题**，过一会儿点「重试」。 |
| `js/detail.js` | 这条核查档案没能读出来，可能是网络不通，或数据服务暂时不可用。 | …可能是网络波动，也可能是本站依赖的服务没起来——不是你的操作有问题。 |
| `js/forum.js` | 帖子列表没读到，可能是网络抖动。… | …可能是网络波动，也可能是本站依赖的服务没起来——不是你的操作有问题。… |

`data.js` 的默认文案抽成常量 `DEFAULT_ERROR_DESC`，杜绝「四处各自描述同一个错误」再度发生。

## 四、判据（正反对照，同一探针）

本机天然是实验场：`cdn.jsdelivr.net` 不通、`fastly.jsdelivr.net` 通。所以**修复效果不需要等线上验证**。

探针 = `verify/probe-sdk-fallback.js`（本地静态服务 + 真浏览器 + 手机宽度）：

| | 正例（仓库原版，含兜底） | 反例（`make-bust-copy.js` 摘掉兜底的副本） |
|---|---|---|
| SDK 请求经过 | `cdn` failed → **`fastly` 200**（第三个 unpkg 不再请求） | `cdn` failed，**再没第二次尝试** |
| `window.WorkBuddyCloud` | ✅ 装上 | ❌ 缺失 |
| 计数行 | 「本月榜 · …共 15 条」 | 「数据未就绪」 |
| 错误说明 | （无错） | **新版不甩锅文案**（顺带验证 3.2 生效） |

两条都成立，才证明「是兜底在起作用」而不是「本来就没坏」。

> 过程中还修了探针自己两处 bug：①`path.join` 在 Windows 产出反斜杠，与正斜杠 ROOT `startsWith` 不匹配 → 整站 404（Day 26 踩过同款）；②反证副本的正则 `[^<]*` 撞到内联 `<script src=` 提前收尾，改为按行过滤。**修验证工具时要先怀疑工具本身。**
